Receipt alerts now include passphrase wallets

O que mudou

On iOS and Android, wallets with a passphrase were left out of the receipt alert, so an EVM token received in one never notified. The wallet already sits in the wallet list inside the vault, and the alert file holds every watched wallet's addresses, so leaving it out protected almost nothing. It now joins like any other wallet once its words and passphrase are confirmed. The settings note says so in all 12 languages.

23 de outubro de 2026

Receipt alerts: a second opinion on every network, checked address by address

O que mudou

Second security review of Oct 23, in both apps:

  • outside the UTXO networks, the asset that changes (or the starting balance) is read again from a provider run by a different company. On the way up the lower value counts, on the way down the higher one, and at the start both must match; without confirmation, the last seen balance stays. A single RPC can no longer invent 'Received 10,000 USDT';
  • UTXO networks: the seen balance is kept per address. Pinned provider and witness must match exactly, including the starting balance, and a provider that is down only silences its own addresses. On Litecoin and Dogecoin, only owners that don't read the other network come first;
  • price by id only while the recognition is still valid.

iOS: only the logos from the list and from Market are stored on disk; logos of unlisted tokens stay in memory only. The folder is deleted when the wallet is removed and on erase all.

23 de outubro de 2026

Security review of Oct 23: receipt alerts, block proofs and providers

O que mudou

In both apps:

  • receipt alerts: a fixed provider for the whole list (salted HMAC), with no fallback. When the balance changes, a provider from another company checks both ways; without confirmation, the seen balance stays. This closes the fake alert with the fixed provider down and the one that lowers the balance only to bring it back;
  • alerts: an EVM token that wasn't read doesn't count as sent;
  • alerts: a normal wallet wins over a watch-only one with the same address;
  • alerts: the salt is drawn again if it's missing;
  • block proof: a witness from another company is required, and nothing above the tip;
  • status: confirmed only with two companies or with the proof, and without a tip it stays pending; status and fee ask the full providers first;
  • a single company in front of a network family (EndpointsFamilyTests): Solana through its own RPC, Aptos through Sentio, Litecoin between litecoinspace and Bitcore, Dogecoin through Atomic;
  • swap: CoW's split sample goes with the random address, and the aggregator cache works again (without the owner in the key);
  • price alerts: a 10^21% change no longer breaks the check.

iOS: the background alert runs at most once an hour. Android: updating replaces the 20-minute schedule with an hourly one.

Privacy: receipt alerts only by the owner, lock screen and clipboard

O que mudou

In both apps (privacy audit, Oct 22, 2026):

Litecoin: inclusion proof (SPV) with scrypt

O que mudou

The work of each header is measured with scrypt (N=1024, r=1, p=1), with a floor of 16 times the target of Oct 22, 2026. Blockbook is the second company that checks the block at that height. With no proof provider online, Litecoin falls back to the previous consensus; a proof that arrives and doesn't add up is always refused. Header cache separated by network.

22 de outubro de 2026

iOS and Android: Bitcoin confirmed only with an SPV proof

O que mudou

Coins to send and confirmed receipts require proof that the transaction is in a mined block: a Merkle path up to the header root, a header with the work of its own target and a target never easier than the floor (16x that of block 972,695), up to six chained headers, and the same block at that height from a provider run by another company when it answers. Before, a provider could invent a transaction with the right txid paying the wallet and it showed as confirmed.

Coins without proof go to the unverified ones; receipts without proof stay pending. On for Bitcoin with the app's providers; proven headers are cached for the session. Tests with real data from block 972,600.

iOS and Android: consensus only between providers run by different companies

O que mudou

Each provider gets its owner (operatorName). The first two of any consensus are from different companies, and two endpoints from the same company count as a single answer (ProviderPool.agreeing and Quorum.gather/agree/collect). Ripple's s1 and s2 servers now count as one company: if xrplcluster went down, the XRP Ledger consensus would have been Ripple agreeing with itself.

22 de outubro de 2026

Android: audit fixes before the Play Store, and the CoW floor in both apps

O que mudou

PIN vault (format 2): the PIN-derived password goes through an HMAC key in the Keystore and becomes the AES key of the wrapper. In format 1 it was only AAD, and KeyMint returns the plaintext before checking the tag: anyone running code in the app would get an offline verifier. Format 1 can only be opened (emulator test vaults).

  • Android 11: setHideOverlayWindows only from API 31; on 30, a touch with a window on top is refused (filterTouchesWhenObscured).
  • Accessibility: the window marked as sensitive data (API 34), and no autofill.
  • Lock: locks when the screen turns off, and a recreated Activity goes through the automatic lock; a cover hides the wallet until the core answers.
  • Without a screen lock on the phone, the vault doesn't open and the screen explains why.
  • Safe Keyboard: turning it off asks for the PIN; password field without the globe and never on third-party keyboards.
  • Secrets through the bridge with the length up front (a passphrase with a line break arrived truncated); JNI strings in UTF-16 (emoji).
  • Attempt counter with fsync of the folder; AAD zeroed after use.
  • Notifications carry an app token (an outside intent doesn't navigate); taskAffinity.
  • Envelope saved with "wt" and checked by reading it back.
  • Support: six BIP-39 words in a row, as on iOS.
  • A token quote with quadrillions of units no longer crashes the app.
  • The hardware check also looks at the PIN key and at Android 11.
  • Build: no configuration cache when signing; the release refuses a debug core; verificar.sh covers the Android Swift.
  • iOS and Android: without a reference price, CoW also has a 5% floor against the aggregators.

versionCode 1002.
